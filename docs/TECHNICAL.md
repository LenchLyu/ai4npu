# ai4npu 技术记录与 AI 协作说明

## 1. 项目目标与边界

项目是一个面向 MNIST 10 类分类的 FPGA CNN 推理原型。目标是学习 INT8 数据表示、3×3 卷积计算、池化、全连接、AXI DMA 与 PS/PL 协作。它固定针对仓库中的网络和整数参考模型；不具备运行任意网络或 YOLO 模型的能力。

目标板为 AMD Zynq UltraScale+ ZCU104，器件 `xczu7ev-ffvc1156-2-e`，工程工具为 Vivado 2026.1。当前尚未进行开发板测试，不能据此声称整机推理、实板时序或准确率通过。

## 2. AI、人员与技术流程

项目由学习者与 AI 协作完成。学习者提出网络和项目目标，使用 PyTorch 完成训练和量化过程，实践 Vivado，编写/重写实验性的卷积、池化和全连接模块并参与讨论。此前的训练与实验使用过 ChatGPT 辅助，历史对话并未完整记录每个模型版本，因此不推断其具体型号。

OpenAI Codex（本次会话的 GPT-6 系列 AI 编程代理，**具体模型变体未在项目记录中确认**）在用户授权下检查现有工程和量化数据、通过 Vivado 工具配置和连接 IP、实现并连接固定网络的 RTL 控制数据通路、创建自检仿真、查看综合/实现报告，并整理本次技术文档和仓库。Codex 使用了本地 `vivado-ip-configurator`、`vivado-simulate-rtl` 和 `vivado-revision-control` 工作流；AMD Vivado/XSim 负责实际工程生成、综合、布局布线和仿真。仓库中的计算核心与工程配置包含 AI 生成或修改的内容。

采用的技术流程：

```text
MNIST 数据准备
    → PyTorch 定义 CNN、训练与 FP32 评估
    → 离线整数参考模型、INT8 权重量化及 INT32 偏置
    → 导出分层参数、输入样本和 golden logits
    → 制定 DDR 数据包 / AXI Stream 传输格式
    → RTL 核心 + DMA/PS/时钟/复位 Block Design
    → 核心自检仿真 → 综合 → 布局布线与时序报告
    → 待完成：系统级仿真、Vitis 编译和实板验证
```

AI 生成内容和工具报告均需要人工审阅；本记录不把 AI 的实现过程等同于独立完成或实板验收。

## 3. 网络和数据格式

| 阶段 | 输入形状 | 输出形状 | 权重 |
|---|---|---|---|
| Conv1 | 1×28×28 | 4×26×26 | 4×1×3×3 |
| ReLU / MaxPool1 | 4×26×26 | 4×13×13 | — |
| Conv2 | 4×13×13 | 8×11×11 | 8×4×3×3 |
| ReLU / MaxPool2 | 8×11×11 | 8×5×5 | — |
| Flatten / FC | 200 | 10 | 10×200 |

两个卷积层 kernel=3、stride=1、padding=0，池化 kernel=2、stride=2。由于 11×11 的池化结果为 5×5，第二层最后一行和列不会进入池化；核心按池化窗口调度，仅计算需要的卷积位置。

量化采用对称有符号 INT8 输入/权重、INT32 偏置/累加，ReLU 后输出饱和至 `[0,127]`，nearest-even 舍入。卷积重缩放为 Conv1 右移 8 位、Conv2 右移 7 位；FC 保留 INT32 logits。精确 scales、权重格式和参考样本保存在 `model/quantized/mnist_cnn_int8.json` 与 `model/fpga_vectors/metadata.json`。

完整输入包为 3,196 字节，包含全部两层卷积和 FC 的权重及偏置，最后是 784 字节输入图像。偏置为小端 INT32；权重数据依照 `metadata.json` 所述的 OIHW / class-major 排列。64 bit AXI Stream 最后一拍 `TKEEP=0x0f` 且 `TLAST=1`。输出为 40 字节、10 个小端 INT32 logits，最后一拍标记 TLAST。

## 4. 计算模块与调度

`rtl/mnist_stream_core.sv` 负责接收/拆包、参数和特征缓存、网络层的状态调度、卷积偏置累加、ReLU 与重缩放、FC、结果输出。输入一次只处理一个推理包，权重每次推理重新加载。当前实现收到一个 64 bit beat 后逐字节写入缓存，并用 TREADY 对上游施加背压。

`rtl/conv2d.sv` 在输入窗口与卷积核同时握手后，计算九个 INT8 有符号乘积之和，输出 20 bit 部分和。它是 3×3 点积运算单元，而非典型的逐拍传递数据的 3×3 脉动阵列。Conv2 的四个输入通道分次调用该模块并由控制器累加，再加对应偏置。

`rtl/maxpool2d.sv` 对四个 INT8 值求最大值。控制器按池化窗口依次完成四个卷积结果及池化，缓存池化后的数据。FC 计算写在 `mnist_stream_core.sv` 内部，用一个逐项乘加过程计算每个类别，而非实例化独立 `fully_connected.sv`。

## 5. Block Design 与软件接口

PS 经 SmartConnect 访问 DMA 的 AXI-Lite 寄存器，DMA 控制地址为 `0xA0000000`。DMA 的 MM2S、S2MM 经内存互连连接 PS HP0 DDR 路径；两个 Stream 端口连接计算核心。工作时钟由 PS 时钟经 Clocking Wizard 产生，配置为 100 MHz，Processor System Reset 负责复位。

`software/main.c` 是一个待验证的 Vitis standalone 示例：准备输入包，清理 CPU 缓存，先启动 S2MM 接收、再启动 MM2S 发送，等待传输完成并比较 logits。实际 BSP 生成的宏、缓存一致性、内存映射、DDR 可访问性和超时/错误处理需要板级核对。该示例不是 Linux 驱动。

当前核心 `frame_error` 没有接到 PS 可读的状态寄存器，非法包可能令核心保持在错误状态，需复位。DMA 中断没有用于示例的软件流程。

## 6. 验证记录

| 项目 | 结果 | 范围 |
|---|---|---|
| PyTorch FP32 / 整数参考模型 | 已保存报告：测试集各 98.18% | 软件评估，不是 FPGA 结果 |
| XSim 核心仿真 | 3 张样本的 30 个 logits 与软件整数参考完全一致 | 仅计算核心，含输出背压；不包含 PS、DDR、DMA |
| 综合 | 已完成，核心独立综合约 44,160 LUT、32,648 寄存器 | 部分数组被实现为寄存器 |
| 布局布线 | 当前工程报告 WNS +1.370 ns，已设置约束满足 | Vivado 2026.1、当前 ZCU104 器件及约束 |
| 位流 | 先前的实现任务已生成 | 不能替代上板验证；仓库不包含生成位流 |
| 板级 / Vitis | 未验证 | 不宣称 DMA 端到端或板上准确率成功 |

全工程布局后报告记录约 46,773 LUT 和 38,613 寄存器，属于该次实现的估计。不同工具、约束与配置可能得到不同结果。Vivado 顶层综合报告中分开综合的 IP 可能显示为黑盒，不能把其 0 LUT 直接解释为全工程资源。

## 7. 已知局限与后续方向

1. 先进行 DMA + 核心的系统级自检仿真，并对异常长度、TKEEP、TLAST 和复位进行测试。
2. 导出硬件平台、编译 PS 软件并在 ZCU104 上检查 DDR、DMA、缓存一致性与结果。
3. 改进权重驻留、片上存储/BRAM 推断和地址调度，减少寄存器和大选择器。
4. 增加核心状态和错误报告、面向不同层/不同模型的可配置接口。
5. 经过系统验证后，再考虑向更复杂网络扩展。
